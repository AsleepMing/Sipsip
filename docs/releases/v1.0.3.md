# Sipsip v1.0.3 Release Notes

Release date: 2026-06-19

Sipsip `v1.0.3` is a focused performance and polish release that fixes batch deletion lag, input dialog focus issues on Windows, and tightens the Daily / Work mode isolation boundary.

## Short GitHub Release Description

Sipsip v1.0.3 fixes batch deletion performance for large index-range deletes, adds debounced clipboard-change event merging, fixes themed input dialog focus on Windows, and removes hardcoded version strings from the update UI.

## Highlights

- **Batch deletion fix**: Large index-range deletions (e.g. `13-121`) no longer cause UI lag. The frontend now calls a single `delete_clipboard_entries(ids)` backend command instead of issuing per-item concurrent deletes.
- **Event debouncing**: Dense `clipboard-changed` events are merged with an 80ms debounce window in `useClipboardEvents` to prevent refresh storms from any bulk deletion path.
- **Input dialog focus fix**: The themed `ConfirmDialog` input for index-range deletion now correctly receives keyboard focus on Windows without triggering system alert sounds. Focus, mouse-down, and `activate_window_focus` are coordinated; keydown events are prevented from bubbling to global keyboard navigation.
- **Hardcoded version removal**: The update progress text no longer embeds a hardcoded version number, avoiding stale strings across future releases.

## Detailed Changes

### Performance

- Added `delete_clipboard_entries(ids)` backend command that deduplicates, skips pinned items, deletes by each entry's real mode, and emits a single `clipboard-changed` event.
- Frontend index-range deletion now maps visible indexes to entry IDs and calls the batch command once.
- `useClipboardEvents` applies 80ms debounced merging on dense `clipboard-changed` events.

### Bug Fixes

- `ConfirmDialog` input field: added `activate_window_focus` calls on auto-focus, mouse-down, and focus events; blocked `keydown` propagation to prevent global keyboard navigation interference on Windows.
- Removed hardcoded "正在同步 1.0.0 核心资源..." text from `SettingsFooter` update progress UI.

### Work Mode Isolation (continued from v1.0.0)

- Live `clipboard-updated` event filtering by mode is confirmed working.
- Non-persistent session history mode filtering is confirmed working.
- Work-mode delete, clear, recent-cleanup, post-paste delete, and persistence quota eviction all use the no-tombstone path.
- Cloud-sync remote deletion only affects Daily-mode records.
- Single-entry delete reads the target entry's real mode before deciding whether to write a cloud-sync tombstone.

### Publishing

- Updated version metadata to `1.0.3` across `package.json`, `package-lock.json`, `src-tauri/Cargo.toml`, `src-tauri/Cargo.lock`, and `src-tauri/tauri.conf.json`.
- Updated `README.md` and `README.zh-CN.md` with v1.0.3 release information.
- Added this release note document.

## Upgrade Notes

If upgrading from v1.0.0:

- No database migration changes; existing data is fully compatible.
- The update progress UI no longer shows a hardcoded version string.
- All v1.0.0 features (Daily/Work modes, index badges, cleanup actions) remain unchanged.
