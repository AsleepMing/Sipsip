# Sipsip v1.0.6 Release Notes

Release date: 2026-06-26

Sipsip `v1.0.6` is a patch release that stabilizes pinned clipboard items in Work mode.

## Short GitHub Release Description

Sipsip v1.0.6 fixes Work-mode pinned items appearing to lose their pinned state after duplicate-content refreshes or later clipboard recaptures.

## Fixes

- Preserved existing `is_pinned`, `pinned_order`, and tags when duplicate-content handling reuses an existing clipboard row.
- Reused protected database rows for pinned/tagged Work-mode records even when global persistent storage is disabled.
- Returned the backend's full clipboard entry from `toggle_clipboard_pin`, so the frontend updates from persisted state instead of optimistic local guesses.
- Centralized frontend clipboard ordering so event inserts, filtering, pin toggles, and drag reordering all respect the same pinned-order rules.
- Added affected-row checks for pin updates and existing-row saves to prevent false-success UI state.
- Adjusted non-persistent session trimming to remove ordinary transient items before protected pinned/tagged records.

## Root Cause

Work-mode pinned items can be stored in the database even when normal clipboard persistence is disabled, because pinned and tagged items are protected from cleanup. When the same content was copied again later, duplicate-content handling could create or emit a fresh entry with default `is_pinned = false`. The database record was usually still protected, but the frontend received an unpinned update and the item appeared to lose its pinned state.

```bash
npx --yes vitest@4.1.9 run src/shared/hooks/historyFetchParams.test.ts src/shared/lib/utils.test.ts src/shared/lib/clipboardSort.test.ts --reporter=dot
```

## Upgrade Notes

- No database migration changes.
- Existing clipboard history, tags, snippets, and settings remain compatible.
- Work-mode content still does not participate in cloud sync by default.
