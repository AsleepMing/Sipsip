# Sipsip v1.0.0 Release Notes

Release date: 2026-06-19

Sipsip `v1.0.0` is the first stable independent release of this fork. It focuses on a clean publishing baseline, practical clipboard cleanup, and safer separation between daily clipboard history and temporary work content.

## Short GitHub Release Description

Sipsip v1.0.0 introduces Daily / Work clipboard modes, recent-history cleanup, visible index badges, index-range deletion, themed cleanup dialogs, and a cleaner dependency baseline for independent publishing.

## Highlights

- **Daily / Work modes**: Switch between regular daily clipboard history and isolated work history from the app header.
- **Work-mode privacy boundary**: Work-mode records are excluded from cloud sync and work-mode cleanup avoids cloud tombstone writes.
- **Recent cleanup**: Clear clipboard records from the current mode for recent windows such as 1 hour or 24 hours.
- **Visible index cleanup**: Show indexes for the currently visible list and delete by a visible index range such as `3-10`.
- **Themed range dialog**: Index-range deletion now uses the app's themed confirmation dialog instead of the native browser prompt.
- **Dependency cleanup**: Removed unused development dependencies to reduce audit noise and publishing surface.

## Detailed Changes

### Clipboard Cleanup

- Added `clear_recent_clipboard_history(duration_ms)` for current-mode recent cleanup.
- Added visible index badges based on the current filtered, searched, and sorted list.
- Added index-range deletion that maps visible indexes back to clipboard entry IDs.
- Kept pinned records protected during index-range and recent cleanup flows.

### Daily / Work Mode

- Added `clipboard_mode` to clipboard records, settings state, startup settings, database schema, and migrations.
- Scoped history queries, searches, counts, duplicate checks, clear operations, and cleanup commands by mode.
- Scoped non-persistent session history by mode to avoid cross-mode cache pollution.
- Filtered live `clipboard-updated` UI events by mode so records from the other mode do not flash into the current list.
- Limited remote cloud deletion application to Daily-mode records.

### UI Polish

- Added a Daily / Work segmented switch in the header.
- Added confirmation when leaving Work mode, with options to keep or clear unpinned and untagged work cache.
- Replaced native index-range prompt with the shared themed dialog input.
- Added localized strings for cleanup, indexes, and clipboard modes.

### Publishing Baseline

- Updated app version metadata to `1.0.0` in npm, Cargo, and Tauri config.
- Expanded English and Simplified Chinese README files for GitHub publishing.
- Added this release note for GitHub release descriptions and changelog use.

## Build And Verification

Verified on Windows:

```bash
npm run build
cd src-tauri && cargo check
cd src-tauri && cargo test test_save_and_get_history
npm run tauri:build
```

Known non-blocking warnings:

- Vite reports an existing dynamic/static import chunk warning for `@tauri-apps/api/event.js`.
- Rust reports the existing `pull_remote_settings_snapshot` dead-code warning.

Current Windows release output:

```text
src-tauri/target/release/sipsip.exe
```

The current Tauri bundle targets are `dmg` and `app`, so Windows installer bundles are not generated unless the bundle configuration is adjusted.

## 推送到 GitHub 前建议

1. 检查 `.env.example`、`src/shared/config/brand.ts` 和 `src-tauri/tauri.conf.json` 中的发布信息。
2. 在本地 `.env` 中设置自己的 `VITE_APP_GITHUB_URL`、`VITE_APP_WEBSITE_URL`、`VITE_FEEDBACK_EMAIL`。
3. 如果暂时没有自己的更新端点，保持 `VITE_ENABLE_UPDATER=false`。
4. 如果需要 Windows 安装器，先调整 `src-tauri/tauri.conf.json` 的 bundle targets。
5. 使用本文件的 “Short GitHub Release Description” 作为 GitHub Release 简介。
